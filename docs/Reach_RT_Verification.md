# 検証画面のボタン切替

2026-09-25、通常画面と研究ライブ画面の往復を追加。研究工程はG4-04完了・全体28/38・G4は4/5のまま。次はG4-05「予備実験の終了判定」。今回のUI追加で研究上の合格や性能を再認定しない。

## 開き方

### Visual StudioからF5で起動する場合

1. `TR2.sln`を開き、スタートアッププロジェクトを`GE3`にする。
2. 実行中ならShift+F5で停止し、変更されたプロジェクトの再読み込みを求められたら読み込む。
3. Ctrl+Shift+BでビルドしてからF5で起動する。
4. 左側「Network Lab」の一番上の **Research Live - T2** を押す。F1でUIを隠している場合は左上の **Research Live** を押す。
5. 研究画面で受信映像、認識マーカー、ロボットの位置・動作、UDP指令・通知状態を確認する。
6. **通常画面へ戻る**を押すと、通常の映像通信画面へ戻る。再びResearch Liveを押すと新しい実行を開始する。

外部のcmdから起動する必要はない。Visual Studioのローカルデバッガー設定は、起動先`$(TargetPath)`、作業フォルダー`$(ProjectDir)`をプロジェクトで明示する。Debug／Development／Releaseの全構成に適用し、通常のビルド出力先は維持する。

ライブはG4-04の両情報版・T2・20秒の設定で実際に動く。20秒後も画面を保持する。途中で戻るとその試行は中断として保存し、完了扱いにはしない。右上の×はアプリの終了。通常画面へ戻った際は初期設定から再起動するため、直前にUIで変更した一時設定は引き継がない。

保存済み結果を見る場合は、その下の **Reach-RT Results** を押し、開いた検証ページのG4-04／G4-03／G4-02ボタンを使う。ライブ実行と結果閲覧のボタンを分けた。詳細な実装・検証は[ライブ切替説明](Reach_RT_Live_Switch.md)を参照。

### アプリを起動せず結果だけ見る場合

1. `tools/open_reach_verification.cmd`をダブルクリックする。
2. 上部の「G4-04 比較」「G4-03 選択」「G4-02 予測」を押すと、同じページ内の結果が切り替わる。
3. 結果が枠内に表示されない場合は「この結果を別タブで開く」を押す。

初期表示は最新のG4-04。各タブの選択はURLの末尾へ反映し、ブラウザーの戻る・進むに対応。タブにはTabキーで移動し、左右矢印・Home・Endでも切り替えられる。インターネット接続やPythonの実行は不要。結果HTMLと関連ファイルが同じプロジェクト内にあることが前提。

## アプリから開く

今回のライブ切替はVisual Studioからの再ビルド・F5起動で使う。`tools/open_reach_app.cmd`が指す`artifacts/reach_viewer_20260925/bin/Release/GE3.exe`は、以前の結果閲覧ボタン追加時のビルドであり、今回のライブ切替版ではない。

研究モードとしてこの更新版exeを起動した場合は、計測終了後に「検証結果を開く」ボタンが有効になる。実験中のブラウザー起動による負荷を避けるため、計測中は無効。従来の研究ライブ用起動ファイルは各工程の旧exeを使うため、この新ボタンは追加されない。結果の閲覧だけなら上記の検証ページ起動ファイルを使う。

生成済みの古いexeには新ボタンは表示されない。Visual Studioではソースを再ビルドしてF5で起動する。`open_reach_app.cmd`はVisual Studioを使わない場合の補助起動手段である。

## 実装の意図と構造

`Reach_RT_Verification.html`が3つの固定済み結果HTMLをiframeへ表示する。結果本体を書き換えず、表示先のみ切り替える。通常アプリのImGuiボタンと研究モードのWindowsボタンは、共通の`ReachReportNavigation.h`から検証ページを開く。プロジェクトの作業フォルダーまたはexeの親階層から探索し、特定PCの絶対パスには依存しない。見つからない場合やブラウザー起動失敗時には案内を表示する。

説明例：「研究の結果を探しやすくするため、アプリから検証ページを開くボタンと、工程ごとの結果を切り替える共通画面を追加しました。元の実験結果や選択器には手を加えず、保存済みの証拠を読む表示層として実装しています。」

## 確認範囲

Releaseビルド成功。HTMLの3ボタン・参照先・ID重複なし、JavaScript構文、DOM代替を使った初期表示・各切替・リンク先・キーボード・履歴・不正キーの復帰を確認。ブラウザーで実際にクリックした確認とは区別する。G4-04／03／02の固定証拠104／97／95ファイルのハッシュは維持。

F5向けの追加確認では、Debug構成に既存の`BCryptHash`未宣言エラーが見つかった。Windows 8を対象にするDebug設定でも使えるCNGの生成・入力・完了APIへ変更し、同じSHA-256を生成するよう修正。Debug x64ビルド、既知ハッシュ値を含む基盤681検査、Debug版の2秒headless起動とexe・入力設定・実効設定のSHA-256照合が合格した。検証用出力だけを`artifacts/reach_vs_ui_20260925`へ分離し、F5用の通常出力先は変更していない。Visual Studio自体のF5操作・画面の目視は未実施なので、ユーザー側ではCtrl+Shift+Bの後にF5で起動する。

ブラウザー自動操作はローカルfile URLがセキュリティポリシーで拒否されたため、目視でのレイアウト・ボタン操作は未確認。通常映像モードの短時間スモーク検証は復号141記録・表示96枚・正常終了で合格した。研究性能の再比較やG1の18姿勢再実行は行わない。ビルドと確認記録は`artifacts/reach_viewer_20260925/verification`へ保存。初回のPowerShellビルドは環境変数Path/PATHの重複で失敗し、環境キーを正規化するPython起動で成功した。
