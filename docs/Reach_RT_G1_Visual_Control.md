## 1. 専門の場で説明する要約

> 実際のH.264とUDPを通った受信画像から、既知マーカーの位置と形を読み取り、ロボットの位置・向きを推定して移動指令を作る機能を実装しました。制御器にはシミュレータの真の座標を渡しません。撮影時刻から画像の古さを判定し、未検出・曖昧な推定・急な推定の飛び・期限切れでは停止指令を出します。どの画像がどの指令の根拠になったかを記録し、真値との比較は評価専用の経路で行います。現在は指令をPC内で直接適用する診断段階で、次に逆方向のUDPと通信断時の制動を接続します。

本体はC++。Pythonは条件設定・起動・検証・記録の整理に使う。認識や制御をPythonへ移した構成ではなく、OpenCV等の新たな依存ライブラリも追加していない。

## 2. 実装内容と意図

| 実装 | 入力 → 処理 → 出力 | 目的 |
|---|---|---|
| `ReceivedLuma` | 復号した輝度画素、サイズ、照合済みframe/stream ID、撮影/受信時刻 | 制御へ渡せる情報を型で限定する |
| `MarkerRecognizer` | 黒い領域の抽出 → 輪郭直線・四隅 → 内部4×4模様の照合 → 位置・向き | 実画素を経由した観測を作る |
| 姿勢の妥当性検査 | 辺長・画像境界・正の奥行き・再投影誤差・複数候補・画像履歴 | 見つかった形を無条件に正しい位置と扱わない |
| `RemoteTaskController` | 最新の画像推定・既知目標・共通時計 → 状態遷移 → 速度・角速度・絶対期限 | 全通信方式で共通に使う固定制御器を用意する |
| ローカル指令適用 | 生成済み指令 → 期限判定 → 仮想ロボットの加減速付き更新 | G1-05のUDP受信器に置き換える前に指令の意味と動きを確認する |
| 評価・履歴 | 撮影時の真値、画像推定、生成/適用指令を別々に記録 | 誤差と時刻の対応を後から独立に検証する |
| 画面 | 受信画像の検出枠、画像由来の推定、使用画像番号・年齢、指令と停止理由 | 何を見て、なぜ動いた／止まったのかを説明する |

実装本体は[ReachVisualControl.h](../research/ReachVisualControl.h)、[ReachVisualControl.cpp](../research/ReachVisualControl.cpp)。これらは`RobotWorld`、`RobotTruth`、初期位置の設定を受け取らない。マーカーと目標の既知の配置は受け取ってよい前提情報であり、現在姿勢の真値とは区別する。

```text
仮想世界 → カメラ画素 → H.264 → RNVP / localhost UDP → 復号画素
                                                         ↓
                                            ID・撮影情報の照合
                                                         ↓
                                            既知マーカー → 画像推定
                                                         ↓
                                       固定制御器 → 期限付き移動指令
                                                         ↓
                                         ローカル適用 → 仮想世界

真値 ──→ 評価ログ・俯瞰表示のみ（認識器・制御器への戻り経路なし）
```

ここでのローカル適用はG1-04の診断用。双方向UDP・回線の通信量計上・指令の配送保証を実装したとは扱わない。

## 3. 前提と推定方法

- 既知の0.24 m角マーカー、内部パターン`8B35`、T1ではx=4.0 m、T2ではx=2.8 m、y=0、高さ0.35 mを使う。寸法・配置・タスク目標は変更していない。
- 較正済み640×360、水平FOV70度、カメラ前方オフセット0.10 m、高さ0.35 m、歪みなし。平面移動でカメラのpitch/rollは固定。一般的な未知姿勢・未知照明の単眼認識器ではない。
- 診断番号の先頭40行を検索・模様照合から除外する。画像内の番号をロボット位置へ変換する処理はない。
- 黒枠の連結領域を探し、各辺の複数画素から直線を当てはめる。白黒境界の中間輝度を積分して、画素単位より細かい辺の位置を求める。
- 四隅と既知平面の対応からホモグラフィ（平面同士の射影変換）を求める。既知のカメラ高・pitch/rollという制約の下で、位置とyawを画像上の誤差が小さくなるように調整する。初期yawを−0.6/0/+0.6 radに分けて解を探す。
- 最短辺20 px以上、四隅が診断帯以外の画像内、黒枠/模様一致、正の奥行き、再投影RMS 2 px以下を要求する。複数のマーカーが一致した場合、同程度に合う離れた姿勢候補を画像履歴でも選べない場合は拒否する。
- 同じstreamのframe ID・撮影時刻の逆行や重複を拒否する。stream変更で履歴をリセットする。直前の有効画像から200 ms以内では、移動上限0.30 m/s・旋回上限0.8 rad/sとINITIALの揺れ許容量3 cm/0.04 radを超える推定変化を`pose_jump`として拒否する。
- 撮影から受信側の認識開始まで200 msを超えた画像は`stale_at_receive`。認識時に有効でも、指令生成時に200 msを超えれば`observation_expired`。受信した時点から寿命を延長しない。

最新画像の認識が失敗した場合、その失敗を制御器へ渡す。古い成功画像へ黙って戻さない。画像が届かない場合は最後の推定の年齢が増え、期限超過で停止する。推定速度は有効な画像推定の位置差／撮影時刻差から求め、ロボットの真の速度を使わない。

## 4. 固定制御器と誤差の扱い

| 状態・条件 | 出す指令 |
|---|---|
| `OBSERVE` | 有効な推定がない、古い、不正、または誤差が大きすぎる場合はv=0、ω=0 |
| `APPROACH` | 目標距離ρ、方位差αからω=clip(1.5α, ±0.8)、v=min(0.30, 0.5ρ)×max(0, cos α)。方位差30度超では旋回だけ |
| `ALIGN` | ρ≤0.08 mで並進を止め、目標yawへ向ける。位置誤差が0.10 mを超えたら接近へ戻る |
| `HOLD` | ρ≤0.08 m、yaw誤差≤3度、画像履歴の推定速度≤0.02 m/sなら停止し、推定上の完了を記録 |
| T1の壁余裕不足 | 既知の通路幅・画像推定・誤差余裕・制動中の移動分から余裕を計算。0.05 m未満なら並進停止と向き修正 |

指令は20 Hzで生成し、生成から100 msの**絶対期限**を付ける。指令番号、根拠画像のframe/stream ID、撮影時刻、生成時刻、期限、状態、理由を保存する。ローカル適用も期限を確認するが、指令UDPの重複・順序制御や250 msウォッチドッグはまだ実装していない。停止指令の適用には既存の0.60 m/s²の制動を使う。

画像の位置誤差の余裕は、距離と再投影誤差に応じて増やす。`d`は画像から推定した奥行き、`r`は再投影RMS、`f`は較正焦点距離とする。

```text
k = 2 r d² / (f × 0.24²)
位置誤差の余裕 = 0.02 + 0.015 d + k d [m]
yaw誤差の余裕 = 0.03 + 0.015 d + k [rad]
画像の年齢aによる位置の増分 = 0.30 a + 0.15 a² [m]
```

これは**INITIALの工学的な余裕で、統計的信頼区間や安全保証ではない**。位置の余裕と年齢増分が0.25 mを超える、またはyawの余裕が0.3 radを超える場合は停止する。再投影誤差が小さくても位置が正しい保証はなく、較正と時間整合性の検査を併用する。今回の条件外を含む再較正・制御安定性確認はG1-06以降で行う。

## 5. 画素生成を修正した理由

当初のカメラは各画素の中心１点で白黒を決めていた。小さいマーカーでは透視投影による微小な辺の傾きが画素の丸めで消え、54観測の較正で最大位置誤差0.7605 m、方位誤差0.3611 radを観測した。小さい再投影誤差だけでは不十分な例である。

マーカー面が各画素を覆う面積を計算して輝度を生成し、認識側も境界の中間輝度から辺の位置を求めるようにした。途中の8×8サンプリング版、輪郭補間版の結果も残している。寸法を大きくしたり、真値から推定値を補正したりしていない。描画は全方式共通であり、物理モデルの運動・目標・成功基準は変えていない。

長めの実行で周期上限超過を検出したため、画素ごとの図形クリッピングに使う動的メモリ確保を固定長配列へ置き換えた。上限超過の試行は無効として保存し、許容周期は緩めていない。描画所要時間も`captures.csv`に記録する。

圧縮後の較正では、一時的な推定の飛びで初期誤差幅を超えた試行があった。これを保存した上で、画像履歴の移動上限による拒否と、距離・再投影誤差に応じた誤差余裕を追加した。これは予備段階の共通認識器の調整であり、通信方式間の優位性評価ではない。
