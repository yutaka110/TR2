# Visual Studio起動後の研究ライブ切替

2026-09-25。通常映像画面から研究実行画面へ移り、通常画面へ戻る接続を追加した。工程数は28/38、G4は4/5、研究ゲート4/7。研究の次工程はG4-05。

同日追記（E030）：Development起動で撮影期限超過が発生。Debugに限定していた仮想カメラの最適化をDevelopmentにも適用し、Developmentの実表示20秒×2回が完了した。[原因・修正・検証](Reach_RT_Live_Deadline_Investigation.md)。以下のDebug検証はE029当時の記録。

## 操作

Visual Studioで`TR2.sln`の`GE3`をスタートアッププロジェクトにし、Ctrl+Shift+BでビルドしてF5で起動する。実行中なら先にShift+F5で停止する。

- 通常画面：左側Network Labの **Research Live - T2** で研究実行へ移る。
- 研究画面：**通常画面へ戻る**で通常映像へ戻る。実行途中でも押せる。
- 通常画面：再びResearch Liveを押すと、新規セッションで研究実行を開始する。
- 保存結果：**Reach-RT Results**で既存のG4比較結果をブラウザーへ開く。

F1で通常UIを隠しても左上にResearch LiveとResultsを表示する。研究モードの×はアプリ終了。20秒の実行後も最終画面を保持する。途中で戻った試行は`interrupted`として残す。

## 実際に動く内容

`config/reach_rt_live_demo.json`でG4-04のjoint（復号・作業の両情報）・λ=1・T2・20秒・正常回線を指定する。仮想カメラの画像をH.264で符号化し、RNVP/UDP、復号、認識、逆方向UDP指令を経てロボットを動かす。画面は受信映像とマーカー、観測用マップ、位置・速度、生成／適用指令、通知の状態を表示する。マップの真値は制御へ渡さない。

実行記録は`artifacts/reach_rt_live/sessions/<セッションID>`へ保存する。起動にPythonや別exeは不要。G4-02の予測モデルファイルが同じプロジェクトのartifacts内にあることが前提。設定・モデルがない場合は案内して通常画面へ戻る。

これは操作・説明用のライブ実行であり、固定済みG4-04比較の追加試行には混ぜない。Debugの処理時間、デバッガー停止、GUI操作による計測遅れを研究の性能比較へ流用しない。従来の期限・計測超過の検査を維持し、実行が無効となった場合も成功へ読み替えない。

## 実装の意図と構造

`AppMain::Run()`に画面切替の外側ループを置き、従来処理を`RunLegacy()`へ分離した。ボタンは切替要求だけを立てる。通常の描画ループが終了すると、送受信スレッド、コーデック、ネットワーク、ImGui、GPU・音声・ウィンドウを既存の終了手順で解放し、その後に研究モードを開始する。同時に両系統を動かさないため、ポートやデバイスの競合を防げる。

研究画面から戻ると、研究側の送受信・指令・記録を終了し、同じプロセスで通常画面を作り直す。別プロセスの起動やAppMainの再帰呼出しを使わない。ウィンドウを作り直す際のクラス再登録と残存WM_QUITを処理し、古い終了通知で次の画面が即終了する問題を防ぐ。通常画面の一時的なUI設定は初期値へ戻る。

`ReachLiveNavigation`は通常側の診断・通信環境変数を保存し、研究中だけ独立した設定を適用する。研究が終了または例外で戻った際に元の環境へ戻す。Releaseでもボタン入力を受け取れるよう、ImGuiへのWindowsメッセージ転送を構成にかかわらず行い、終了処理も全構成で行う。

`ResearchUiNavigation`は戻り要求を明示する。戻るボタンを押した場合だけ通常画面へ復帰し、×で閉じた場合はアプリ終了とする。途中の復帰は計測中断として保存し、完了と区別する。古い環境変数起動・headless実験は引数省略時の従来経路を維持する。

研究ライブの描画は専用UIスレッドへ分離した。計測側から画像・状態のコピーを100 ms間隔で渡し、UI側が自分のコピーを描画する。ウィンドウ操作やGDI描画で物理・撮影・制御の時計を直接止めないための構造である。戻り・終了はatomicの通知で計測側へ渡し、終了時にUIスレッドをjoinする。

Debugでは仮想カメラの画素生成が1枚約36 msかかり、30 Hzの撮影を取りこぼすことも確認した。`GE3.vcxproj`で`ReachRobotWorld.cpp`だけを速度優先の最適化へ変更した。画像生成式・撮影周期・期限検査は変更していない。他のモジュールは通常のDebug設定を維持する。このファイル内は最適化によって変数のデバッガー表示やステップ実行が制限される場合がある。

説明例：「通常の映像通信画面と研究用の仮想ロボット画面を、同じデバッグプロセス内で切り替える仕組みを実装しました。切替前に通信と描画を終了し、戻った際に再初期化することで資源の競合を防ぎます。途中で戻った計測を中断として残すため、デモ操作と正式な研究結果を混同しません。」

## 検証

Debug x64ビルドと同一プロセスでの往復・中断・モデル不足の実行試験が合格した。テストは通常画面を30フレーム描画した後、ボタンと同じ切替要求・終了処理を使い、各条件で2回往復して通常画面を計3回初期化する。

| 最終試験 `navigation_04` | 確認結果 |
|---|---|
| 実画面表示・20秒×2回 | 両方で物理2,000／撮影600／制御400刻みを完了。復号画像の識別一致565枚・570枚、ロボットの移動、G4スケジューラ記録を確認 |
| ネイティブUI | 戻るボタンの生成とWM_PAINT 195回・196回を記録。診断がボタンのWM_COMMANDを発行し、同じPIDで通常画面へ復帰 |
| 短時間完了・2回 | 両方で完了後に通常画面へ復帰 |
| 途中中断・2回 | 両方で`interrupted`を保存して通常画面へ復帰 |
| モデル不足・2回 | 研究セッションを生成せずエラーから通常画面へ復帰 |
| 従来の環境変数起動 | 切替引数なしのheadless基盤を2秒実行。物理200／撮影60／制御40刻み、正常終了 |

実行完了と作業成功判定は別である。この試験は接続・復号・移動・画面のライフサイクルを確認したもので、T2作業成功の新たな認定ではない。Visual Studio自体のF5操作、マウスのクリック、画面レイアウトの目視、Release版の今回の接続は未検証。

開発時の失敗も保持した。`navigation_02`の実表示は同じスレッドの描画待ちで時計の追従上限に達し、エラーダイアログ待ちで試験がタイムアウトした。描画分離後の`navigation_03`ではDebugの画素生成が遅く撮影周期を取りこぼした。上記2点を修正した最終版が`navigation_04`であり、失敗記録を成功記録に置き換えていない。

記録は`artifacts/reach_live_switch_20260925/verification`。通常のVS出力先を変更せず、検証用exeだけを別ディレクトリへ出力する。過去の研究exe・固定結果を上書きしない。
