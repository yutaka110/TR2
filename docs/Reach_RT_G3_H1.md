## 1. 実装の意図と結論

H1は「復号状態の情報は、ネットワーク統計と鮮度だけでは得られない判断価値を持つ」という仮説である。今回は、通信が同じで画像も同じ古さなのに、次に送るべきものが異なる例を構成した。「通信統計とAoIだけで常に十分」という主張への反例であり、H1への条件付きの支持になる。一方、追加情報が役立たない条件も明示し、「常に価値がある」という強すぎる解釈は採用しない。

入力は、最後の利用可能画像の撮影時刻、到着済み通知、残り予算・期限、既知の確率モデル。処理は、同じ観測履歴から区別できない状態を確率分布にまとめ、将来の全分岐を有理数で計算する動的計画法。出力は、各初手の成功確率・最適な選択肢の集合・95%成立判定・試験範囲内の予算境界である。

対外説明には次を使える。

> 遠隔制御に使った画像が新しくても、次の差分画像を復号するための参照画像が受信側に残っているとは限りません。この二つを分けた有限モデルを作り、通知を受け取ってから判断する条件で情報の価値を計算しました。同じ予算でも参照状態に応じて送る画像を変えることが有効な例と、通知が間に合わず効果がなくなる例を、再実行可能な証拠として保存しています。

## 2. 本当に同じAoIになる履歴対

AoI（情報の古さ）は `現在時刻 − 最後に利用可能となった画像の撮影時刻` とする。受信・復号時刻との差ではない。

両世界で時刻−2に同じI画像を撮影し、同じ2パケットが同じ遅延1で届き、時刻−1に画像を利用可能にする。制御側はその画像を保持し、現在時刻0ではAoI=2。途中の新規撮影はない。片方は復号器の参照を保持し、もう片方は出力後に参照バッファだけを消去する。バッファ消去は新しい画像を出力せず、制御側に既に渡った画像と撮影時刻を取り消さない。

これにより、過去のパケット到達・遅延履歴そのもの、損失統計、AoI、作業段階、予算、期限、将来のパケット到達確率を揃えたまま、参照保持だけが異なる。[履歴対](../artifacts/reach_g3_h1_20260924/study_01/histories.json)を保存した。参照保持の事前確率は1/2とし、両方式に同じ事前分布を与える。

参照消去は受信側ローカル事象の**モデル上の仮定**である。既存の `NetworkVideoReceiver.cpp` の `MarkReferenceBroken` は復号器のflush・参照同期解除を行うが、今回の独立な消去確率を実機で推定・再現したわけではない。同じネットワーク履歴なら実デコーダが必ずこの二状態になる、と主張するものでもない。作業段階0の実験では、最初の画像は今回の二段階作業を開始する前の観測として扱う。

## 3. モデルと公平な比較

G3-03は変更せず、AoIを追跡する独立したモデルを追加した。

| 項目 | 定義 |
|---|---|
| 隠れた状態 | 参照保持r、作業段階s、最後の利用可能画像の撮影時刻u、未到着通知列 |
| 時間 | 最大4スロット。スロットtの開始に撮影し、成功画像はt+1に利用可能。AoIは直後1となる |
| 回線 | 各スロット2個の潜在的パケット到達結果。到達確率pの独立試行。方式間で同じ位置の結果を使う |
| WAIT | 0パケット。新しい画像は使えず、連続IP鎖の次の参照も失う |
| P | 1パケット。参照があり、パケットが届くと復号成功 |
| P_REPEAT | 同じPの2回送信。参照があり、どちらかが届けば成功。XOR FECではない |
| I | 2チャンクからなる参照不要画像。両方が届けば成功。実H.264のサイズではない |
| 作業 | 利用可能画像ごとに1段階進み、段階2で成功。成功後は吸収状態 |
| 参照消去 | 出力後に確率δで参照を失う。画像・撮影時刻・達成段階は保持。δ=0と1/4を検証 |
| 通知 | 時刻0と各スロット終了で固定サイズの通知機会。dスロット遅れ、独立に確率qで欠落 |
| AGE方式 | 到着したACK、作業段階、最後の利用可能画像の撮影時刻と通知時刻。全観測履歴を使用 |
| REF方式 | AGEの情報に、同じ通知内の参照保持rだけを追加 |
| 費用 | 映像1パケット=1,272 IP byte。通知予約=64×(H+1) IP byte。モデル上の固定費用 |
| 最適化 | 作業成功確率を最大化。同率なら期待通信量、固定の行動番号の順。成功確率で同率の全候補も記録 |

AGEにも作業段階と全履歴を与えるため、わざと弱くした鮮度方式との比較ではない。通知の撮影時刻から古さを更新でき、参照状態を推論できる場合はその推論も許す。未到着通知、未来のパケット結果、未来の参照消去は判断入力にしない。REFも現在の真値ではなく、到着した時点の報告を使う。

両方式は同じ報告機会・サイズを予約し、隠す情報だけを変える。実RSTAの208 byteや実ACK・指令の全内訳を再現した課金ではない。64 byteはモデルの固定予約であり、観測に使えない最終通知や欠落分も予約する。総IP予算Bの表では、映像予算を `floor((B−64(H+1))/1272)` とする。予約だけで超過する24条件は実行不能として除外し、成功確率0の合法方策と混同しない。

AoIは状態遷移と観測に明示的に含むが、このモデルの成功条件は古さによる誤差増大・200 msの画像失効を含まない。AGE/REFはライブB1/B2とは異なる、指定された情報の下での最適解である。今回のIID回線は、G3-03の隠れた良悪回線モデルを置き換える研究全体の仕様変更ではない。

## 4. 最小反例と解析的な成立条件

残り1段階、1スロット、映像2パケット、p=0.9、参照保持の事前確率π=1/2、即時・欠落なし通知とする。初期AoIは両状態とも2。

| 真の参照状態 | WAIT | P | P_REPEAT | I | 唯一の最適行動 |
|---|---:|---:|---:|---:|---|
| 参照なし | 0% | 0% | 0% | 81% | I |
| 参照あり | 0% | 90% | 99% | 81% | P_REPEAT |

最適行動集合は交わらない。AGEは両状態で同じ観測を受け取るので、最適でもIを選び81%。REFは到着した参照通知で選択を変え、`(81%+99%)/2=90%`。改善は9パーセントポイントで、両方式とも映像2パケットを使う。この例ではランダム化した共通行動でも両状態の最適行動を同時には実現できない。

一般の `0<p<1`、`0<π<1` では次が成り立つ。

```text
V_AGE = max(p², π(2p−p²))
V_REF = (1−π)p² + π(2p−p²)
V_REF − V_AGE > 0
AGEは π < p/(2−p) ならI、π > p/(2−p) ならP_REPEATを選ぶ。
境界では両方が成功確率で同率。
```

理由は、参照なしではIの値p²だけが正、参照ありでは `2p−p² > p²` でP_REPEATが唯一最大だからである。双方に正の事前確率があると、状態を区別しない共通行動には必ず厳密な損失がある。1スロットで通知欠落確率qの場合、即時通知なら情報利得は `(1−q)(V_REF−V_AGE)`、通知が判断に間に合わない場合は0となる。

pが0または1、πが0または1、映像予算が0または1パケットの場合、この1スロットの成功確率上の追加価値は0。確率・事前分布・予算の105条件と解析式を照合した。これは上の限定されたモデルについての証明で、任意のコーデックの定理ではない。

## 5. 95%成立領域と負の結果

`F_0.05 = {(初期belief, B, H): V* >= 19/20}` を計算する。95%は仕様の目標をそのまま使い、差が出るように閾値を下げていない。モデルの既知確率に対する厳密値であり、95%信頼区間ではない。

| 条件（p=0.9、即時・欠落なし通知、追加flushなし） | AGE最適 | REF最適 | 判定 |
|---|---:|---:|---|
| 残り1段階、H=1、参照なし既知、総2,816 byte | 81% | 81% | 両方95%未満 |
| 残り1段階、H=1、参照あり既知、総2,816 byte | 99% | 99% | 両方成立 |
| 残り1段階、H=2、π=1/2、総5,376 byte | 96.39% | 98.1% | 両方成立 |
| 残り2段階、H=3、π=1/2、総6,656 byte | 94.041% | 96.39% | REFのみ成立 |
| 残り2段階、H=3、π=1/2、総8,192 byte | 96.0822% | 97.848% | 両方成立 |

最後の2条件では、試験した中で95%を満たす最小総予算がAGEの8,192 byteに対しREFは6,656 byte。差は1,536 byteだが、連続的・全整数予算に対する厳密な最小値や実網の削減量ではない。[境界一覧](../artifacts/reach_g3_h1_20260924/study_01/boundaries.json)は、4期限×3初期参照事前分布×2作業段階×2方式を記録する。結果HTMLに固定総予算×期限の色付き成立表と全分数を表示した。

期限を増やすと通知予約が増えるため、固定総予算では映像パケットが1つ減る境界がある。例えば参照なし既知・残り1段階・総5,376 byteは、H=3では映像4パケットで96.39%、H=4では3パケットとなり81%。期限が長いことの普遍的な悪影響ではなく、宣言した固定予約の制約による結果である。映像パケット予算を固定した期限の単調性は別にテストした。

追加情報が役立たない対照も保存した。

- 全通知欠落、または通知遅延がH以上：両方式の観測が一致し、成功確率も一致。
- 予算0：情報があっても送信できない。
- 初期参照が既知、追加flushなし：ACK・画像の撮影時刻から参照保持を追跡でき、追加の参照通知に価値がない。
- 最小例の必ず成功／必ず失敗する回線：行動を変える成功確率上の価値がない。

さらに、H=3・映像4パケット・残り2段階・π=1/2では、追加flushなしの即時通知でAGE84.645%／REF89.1%。通知を1スロット遅らせると80.19%／81%となる。追加flush確率1/4では、即時通知で72.2925%／85.05%、1スロット遅延で66.52125%／69.55875%。この例でも状態不確かさと通知の適時性を分けて評価できる。全ての遅延・確率に対する一般的な単調性をこの少数例から主張しない。
